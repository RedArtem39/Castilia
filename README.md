# Castilia

Минимальное переносимое ядро браузерного движка для WynlandOS и других ОС. Исходники WynlandOS не входят в этот проект и не изменяются.

## Что уже работает

- Разбор HTML в дерево: элементы, атрибуты, текст, комментарии, 2125 именованных сущностей, автоматические `html`/`head`/`body`, восстановление незакрытых `p` и `li`.
- Базовый CSS: селекторы по тегу, классу, `id`, селекторы потомков, каскад, `!important`, наследование цвета и размера шрифта, встроенный `style`, атрибут `style` и простые `@media` по ширине окна.
- Блочная раскладка, схлопывание соседних положительных вертикальных отступов, простой `display:flex` в строку с `gap`, перенос слов, встроенные элементы, ссылки, `br`, изображения с заданными размерами и построчное представление таблиц, включая разрывы строк во вложенных таблицах.
- Независимый от ОС список команд `FillRect`, `Text`, `Image`.
- Загрузка HTML, связанных CSS, классических внешних JS-скриптов и байтов изображений по HTTP(S) через интерфейс `Fetcher`; относительные адреса ресурсов преобразуются в абсолютные URL.
- Упрощённый режим чтения для сложных страниц: выделяет основной текст и заголовок, выводит изображения и построчно показывает таблицы.
- Собственный небольшой интерпретатор JS на Rust: переменные, арифметика, сравнения, `&&`/`||`, `if`/`else`, функции с аргументами и `return`, обработчики событий, свойства `window`, `document.body`, `getElementById`, `querySelector('#id')`, `createElement`, `appendChild`, `remove`, `textContent`, `setAttribute` и `addEventListener`. Скрипты могут менять DOM; `Page::render` после этого пересчитывает стили и раскладку.

Ядро компилируется с `#![no_std]` и `alloc`; без опционального `host-net` внешних зависимостей нет. Вызывающая сторона предоставляет аллокатор, метрики шрифта (`FontMetrics`), реализацию `Fetcher` и исполнение команд рисования. `Fetcher` отвечает за HTTP(S), TLS, редиректы и разрешение относительных URL. Хостовый пример использует `ureq` и `url`; в WynlandOS можно подключить собственную сетевую библиотеку. `Command::Text.y` означает верх строки в CSS-пикселях. `DisplayList::hit_test` находит элемент по координатам, `Page::click_at` запускает `click` с подъёмом события по родителям. Ввод с клавиатуры и навигация пока не реализованы.

Для повторной отрисовки после события используйте `Page::new(html, css)`, затем `page.render(width, &fonts)`. Передайте полученный `DisplayList` и координаты в `page.click_at(&display, x, y)`, после чего вызовите `render` снова. `load_page` возвращает сессию в `LoadedPage.page`; режим чтения скрипты не запускает. Для внешних скриптов в собственном адаптере доступен `Page::from_document_with_loader`.

## Проверка на хосте

```sh
cargo test
cargo run --example render_svg -- examples/sample.html sample.svg
cargo run --release --features host-net --example browse -- https://example.com/ example.svg
cargo run --release --features host-net --example browse -- --reader https://en.wikipedia.org/wiki/World_Wide_Web wikipedia-reader.svg
cargo run --release --features host-net --example bench -- --live
python tools/visual_bench.py
python tools/live_visual_bench.py
```

`browse` создаёт SVG страницы и печатает число DOM-узлов, команд рисования и неподдержанных конструкций CSS. Он загружает до 16 изображений и встраивает их в SVG. `--reader` включает режим чтения. `bench` создаёт `bench-report.md` с локальными проверками, временем обработки 100 абзацев и проверкой видимого текста на шести реальных сайтах: httpbin, Wikipedia, Rust, W3C, Python и Hacker News. Он также показывает число исполненных, загруженных, пропущенных и завершившихся ошибкой скриптов. Если проверка ожидаемого текста или загрузка сайта не прошла, команда завершается ошибкой. Можно указать собственные сайты после `--live`; для них проверка ожидаемого текста не задана. Хостовые примеры измеряют текст системным шрифтом через `fontdb` и `fontdue`; для точного переноса строк в ОС адаптер должен использовать фактический шрифт её рендерера. SVG-примеры используют `std`, библиотека — нет.

`tools/visual_bench.py` сравнивает снимки восьми локальных HTML-страниц с Chromium и создаёт `visual-report.md` и картинки в `visual_out/`. Для него нужны Python, Pillow, Playwright и установленный браузер Playwright Chromium. Тесты охватывают блоки, проценты, скрытые элементы, отступы, простой Flex, `@media`, изображение и текст. Цель — отслеживать визуальные регрессии, а не объявлять процент совместимости со всем вебом.

`tools/live_visual_bench.py` сохраняет снимки трёх живых сайтов рядом с Chromium в `live_visual_out/` и пишет `live-visual-report.md`. Число отличающихся пикселей здесь служит диагностикой: содержимое сайтов, шрифты и сетевые ответы могут меняться между снимками.

Число команд рисования или успешно загруженный HTML не равны совместимости сайта. Бенчмарк фиксирует конкретные поддержанные и неподдержанные сценарии; время сети отдельно от локальной скорости рендера. Визуальное сравнение охватывает только маленький локальный набор страниц. Для сравнения с другими движками понадобится гораздо более широкий стандартный набор тестов.

## Граница MVP

Это намеренно небольшое подмножество веб-стандартов. Пока нет полного алгоритма HTML5, полноценной табличной раскладки и Flexbox (доступна только простая строка), Grid, позиционирования, CSS-переменных, форм и медиа. JS поддерживает лишь перечисленные выше конструкции: большинство синтаксиса ECMAScript и браузерных API пока не исполняются; модули и `async`-скрипты пропускаются, а ошибки классических скриптов фиксируются в отчёте. Скрипты запускаются после разбора всего HTML, а не в момент встречи тега. На один скрипт действует предел 256 КБ и 2048 токенов, чтобы повреждённый или слишком большой скрипт завершался ошибкой. Ядро скачивает байты изображений, но декодирование и рисование выполняет адаптер; хостовый SVG-пример отдаёт эти байты Chromium. Текст предполагается в UTF-8; другие кодировки требуют адаптера. Обычный режим не воспроизводит сложные сайты вроде Wikipedia точно, а режим чтения показывает основной текст и часть изображений линейно. YouTube пока не поддерживается. Порт в WynlandOS и медиаслой выполняет владелец ОС.
